# 原力反例志 v1.0｜《那些看起来正确却没有成立的战略》

- 状态：`accepted / planning-baseline`
- 栏目层级：旗舰系列层
- 正典接口：A1—C4
- 最高纪律：不以失败羞辱个人，不用单一结果反向证明全部方法错误；专门研究条件、机制、边界和停止规则。

---

## 1. 栏目定位

> 专门研究那些听起来正确、做起来努力、甚至一度获得赞美，却没有转化为用户行动、商业结果、控制权或事业复利的战略。

栏目目的不是制造负面情绪，而是建设原力战略的反证能力：

```text
正确概念
→ 错误条件
→ 错误对象
→ 错误顺序
→ 缺失链路
→ 无效结果
→ 边界与停止规则
```

## 2. 反例六类

### 2.1 有母体，没有市场

自我理解深刻，但没有进入时代、用户贵问题和真实选择。

### 2.2 有品类，没有结果

表达独特，用户能记住，却不能稳定获得承诺结果。

### 2.3 有流量，没有控制权

平台数据很好，但心智、入口、关系和留存仍掌握在外部平台。

### 2.4 有流程，没有交付系统

SOP很多，异常仍必须找创始人，关键质量没有进入组织判断。

### 2.5 有知识库，没有调用

资料持续增加，下一次任务开始前却没有明确读取和加载。

### 2.6 有复盘，没有复利

总结很多Changed Rule，但Task2没有加载证据。

## 3. 每篇固定“反例八问”

1. 当初相信什么；
2. 这个判断在什么条件下原本合理；
3. 实际执行了什么；
4. 哪个关键Action没有发生；
5. 哪项Outcome没有出现；
6. 可能的其他归因是什么；
7. 哪个边界、前提或顺序被忽略；
8. 下一次应该停止、延后、改序还是改对象。

## 5. 证据纪律

每篇必须区分：

- `baseline`：原问题与原假设；
- `action`：真实发生的动作；
- `non-action`：没有发生但被默认发生的动作；
- `evidence`：支撑或反对判断的证据；
- `outcome`：现实变化；
- `attribution`：可能原因与替代解释；
- `boundary`：适用对象、时机和前置条件；
- `stop_rule`：何时不再继续投入。

不得仅凭“最终失败”否定当时全部选择，也不得把复杂失败归咎于个人品格。

## 6. 首篇试点

# 《有知识库，为什么下一次仍然从零开始？》

大纵深：

```text
资料存在
≠ 被找到
≠ 被相信
≠ 被加载
≠ 改变行动
≠ 产生Outcome
```

对应模块：C2、C3、C4。

核心反例机制候选：

- 没有稳定对象和关系；
- 事实、推论、规则混杂；
- 没有任务启动面；
- 没有Human Gate；
- 没有Task2加载回执；
- 资料增加速度高于知识淘汰速度。
