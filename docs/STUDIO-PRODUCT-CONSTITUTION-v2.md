# 原力 Studio Product Constitution v2

- 状态：FROZEN / Phase 0
- 适用范围：`/studio/`
- 产品定位：Producer Mission Control
- 原则：Studio 不是第七个真源，也不是 Content Workbench 的替代品。

## 1. 三层 B 端产品

```text
L1 Studio      → 我现在最应该做什么？
L2 专业作业台  → 这件事具体怎么做？
L3 Workbench   → 系统究竟做了什么，我为什么可以相信？
```

Studio 只承担任务翻译、状态聚合、下一门、Human Attention、Deep Link 与现实回流；底层事实继续由 PMO / Brain / Content Engine / Soul / Taste / Web 及正式部署回执拥有。

## 2. 七条不可破坏法则

1. **No seventh truth source**：Studio 的任何运行状态必须可追溯到 Owner System。
2. **Field-level authority**：一个事实字段只有一个最终法权；冲突必须显式呈现。
3. **Next Gate > percent complete**：不以抽象完成度替代下一道门。
4. **Human attention is scarce**：首页优先聚合需要人类判断、品味、授权和学习的事项。
5. **Published ≠ Used ≠ Validated ≠ Compounding**：页面、作品、发布和真实结果严格分层。
6. **Fail visible**：读取失败显示 STALE / Last Known Good，不把旧事实静默写成最新事实。
7. **No direct Canon write**：v2 仅 Read + Route；未经 Soul Human Gate 不批准 Canon 或 Changed Rule。

## 3. Studio 与 Bao / Workbench 的边界

- Bao：Signal / Radar / Select / Confirm 等专业作业能力，回答“怎么做”。
- Studio：决定哪些信号值得进入经营、当前卡在哪、下一步去哪里。
- Content Workbench：节点、Skill、Prompt、SHA、Receipt、Runtime、Health，回答“系统真实做了什么”。

Studio 可以 Deep Link 到专业工作台，但不得复制其节点、回执或运行账。

## 4. 产品语言

Studio 使用生产者语言：

```text
Signal → Evidence → Judgment → Campaign → Work → Distribution → Reality → Learning
```

内部治理语言继续存在于各真源：

```text
CTX → EVD → DEC → WPK → ACT → OUT → LRN
```

## 5. 目标 IA（分阶段启用）

最终一级导航冻结为：

```text
今日 / 雷达 / 研究 / 战役 / 作品 / 发布 / 学习 / 系统
```

Phase 0—1 不为了 IA 完整度新增空页面；先完成 Truth Projection、LKG、Authority、Conflict 与 Today/Campaign 的真实数据接入。

