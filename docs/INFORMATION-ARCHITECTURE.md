# 原力战略 Web · 信息架构 v2.2

- 状态：`accepted / execution-baseline`
- 核心原则：用户架构回答“我来这里做什么”，建设者架构回答“我们如何持续生产与治理”
- 首次用户目标：30秒理解价值，90秒找到入口，3—10分钟完成一个动作

## 1. 用户可见一级导航

```text
看时代
找原力
做生意
建系统
文章
案例
工具
正典
```

### 看时代
进入原力前哨，回答：世界正在发生什么，这会改变怎样的长期选择？

### 找原力
进入 `/start/?path=A`，只完成A阶段3题。

### 做生意
进入 `/start/?path=B`，只完成B阶段4题。

### 建系统
进入 `/start/?path=C`，只完成C阶段2题。

### 文章
进入 `/articles/`，承担搜索、阅读与精确检索。

### 案例
进入 `/articles/?type=case`，直接筛选案例，不依赖栏目总览。

### 工具
进入 `/tools/`，按用户收益和前置条件选择行动工具。

### 正典
进入 `/columns/canon/`，需要深入时再展开A1—C4完整地图。

## 2. 建设者信息架构

以下结构全部进入 `/about/` 的“关于我们如何工作”，不得再次进入一级用户导航：

```text
主题
栏目
战役
旗舰
发布状态
回写协议
```

- 主题：长期研究方向；
- 栏目：持续内容引擎；
- 战役：阶段性冲突的集中生产对象；
- 旗舰：跨周期思想资产；
- 发布状态：Done / Validated / Compounding；
- 回写协议：Action → Outcome → Changed Rule → Task2。

`/themes/` 与 `/columns/` 继续存在，但成为建设与探索页面，由 `/about/` 统一承接，不再从主导航直接暴露。

## 3. 首页信息流

```text
母叙事＋一个主行动
→ A/B/C真实症状
→ 本周封面
→ 原力前哨
→ 行动工具
→ 三条阅读轨道
→ 商业物种主展
→ 三阶段地图
→ 证据与边界
```

首页负责推荐，不承担完整栏目、主题、文章总账或治理矩阵。

## 4. 3分钟原力导航 v0.2

作用域：

```text
/start/         → 全面导航 9题
/start/?path=A  → 找原力 3题
/start/?path=B  → 做生意 4题
/start/?path=C  → 建系统 2题
```

结果结构：优先验证坐标、判断依据、并列说明（如有）、唯一下一步、边界说明。

规则：

- 历史进度与当前入口冲突时必须让用户选择；
- 并列最高分显式展示；
- 首个推荐按A→B→C上游优先，不暗中偏向后置模块；
- 状态仍是 `navigation hypothesis`。

## 5. 文章与案例

文章中心承担：关键词搜索、类型筛选、标题/症状/概念/模块检索、结果计数。

文章页承担：当前位置、证据等级、来源状态、目录、阅读进度、Outcome Question、具体下一步、返回来源。

移动端不得删除证据和来源信息。

## 6. 工具中心

每张工具卡必须回答：

- 适合谁；
- 需要什么；
- 得到什么；
- 接下来做什么；
- 是否属于基础行动或综合诊断。

工具必须保存输入和最终生成资产；默认值不得被误算为用户进度。

## 7. 纸—场—舱

- `Paper｜阅读模式`：理解机制与证据；
- `Field｜观察模式`：看时代与结构；
- `Cockpit｜工作模式`：完成判断与行动。

三种场景允许外观变化，但必须共享品牌、Header、模式提示、按钮语法、返回路径与Footer信任语言。

## 8. 本地连续性

```text
yuanli-navigation:v0.2
yuanli-journey:last
yuanli-tool:<pathname>
```

允许保存：导航进度、导航结果、工具输入、工具生成资产、继续位置。

本地状态不等于用户身份，不得在未授权情况下跨设备合并。

## 9. 真实性边界

工程Output只允许标记Done。5—8位真人首次成功测试、至少10次真实导航/工具行动、7/30天Outcome、Changed Rule与Task2复用仍需真实执行。
