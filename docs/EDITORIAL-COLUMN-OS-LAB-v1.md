# 原力OS实验室 v1.0

- 状态：`accepted / planning-baseline`
- 栏目层级：常设栏目
- 正典接口：C1—C4，兼容A1—B4
- 最高纪律：公开工程过程，但不暴露密钥、私密资料和未经授权经营数据；构建完成不等于业务Outcome。

---

## 1. 栏目定位

> 公开记录一条高价值判断如何被编译成文脉、大脑、地图、链路、Agent和真实工作界面，以及它在哪里失真、失败和被修正。

它不是软件产品更新日志，而是原力OS的实践证据库：

```text
真实任务
→ 上下文与法权
→ 人机分工
→ 系统假设
→ 构建与Human Gate
→ 真实调用
→ 结果与漂移
→ Changed Rule
→ Task2加载
```

---

## 2. 每期固定“实验十项”

1. Task与贵问题；
2. Baseline：原来如何完成，成本和错误在哪里；
3. 法权：谁能读、写、批准、停止和升级；
4. 系统假设：为什么文脉、大脑、地图或链路可能改善问题；
5. 人机分工：AI做什么，人必须保留什么；
6. Output：代码、页面、Schema、Skill、流程或工具；
7. Action：谁在真实任务中调用；
8. Evidence与Outcome；
9. 漂移、失败、反例和归因边界；
10. Changed Rule与Task2加载证据。

## 3. 首批12个实验题

1. 如何把一次栏目策划写入GitHub并外显为门户；
2. 一个知识库为什么不是一个大脑；

5. 如何把一次咨询蒸馏成可复用Skill；
6. 为什么Agent越强，Human Gate越重要；
7. 一张地图如何真正改变优先级；
8. 如何建立项目启动前的规则加载回执；
9. 什么任务不应该自动化；
10. 如何记录失败而不是只记录成功样例；
11. 如何让Web产生回写候选但不越权修改正典；
12. 如何判断一个OS已经从Done进入Compounding。

## 4. 首期试点

# 《一套栏目策划，如何从聊天进入GitHub，再外显为门户？》

本次门户栏目矩阵可以成为公开安全试点。

### 可确认Output

- 栏目总账文档；
- 七个常设栏目与四个旗舰数据模型；
- 栏目总览页；
- 11个栏目详情页；
- 首页栏目矩阵；
- 主导航更新；
- CI与Pages部署证据。

### 尚不能宣称

- 用户已经理解栏目结构；
- 栏目页提高了阅读深度；
- 用户完成了诊断或工具；
- 栏目体系已经产生内容复利。

### 下一步实验

选择3—5名目标用户完成：

1. 从首页找到最相关栏目；
2. 解释主题、栏目和旗舰的区别；
3. 从栏目进入一篇文章或工具；
4. 记录迷路点、误解与放弃点；
5. 依据证据修改导航或文案。

## 5. 状态纪律

```text
BUILT
产物存在并通过工程验收

USED
真实用户或团队在任务中调用

VALIDATED
有权人类基于证据判断结果变化

COMPOUNDING
新规则在下一次任务开始前被读取并产生证据
```

不得因为仓库、页面或Agent存在就越级标记。

---

## 6. Outcome Question

> 一个真实任务是否在本人缺席或减少干预时仍保持关键质量，并留下可被下一次明确读取的证据和规则？
