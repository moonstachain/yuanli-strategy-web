# 全站用户旅程与交互一致性合同 v1

- 状态：`accepted / implementation-baseline`
- 目标：无论用户从首页、导航、文章、案例还是工具进入，都始终感觉自己走在同一条路上

## 1. 全站状态机

```text
ENTRY
→ ORIENTATION
→ ACTION
→ FEEDBACK
→ RESULT
→ NEXT
→ RESUME
```

每个页面必须回答：

1. 我在哪里？
2. 为什么在这里？
3. 我现在做什么？
4. 我做到哪里？
5. 我得到什么？
6. 下一步是什么？

## 2. 用户信息架构

一级入口：

```text
看时代 / 找原力 / 做生意 / 建系统 / 文章 / 案例 / 工具 / 正典
```

建设者结构：

```text
主题 / 栏目 / 战役 / 旗舰 / 发布状态 / 回写协议
```

建设者结构只从“关于我们如何工作”进入。

## 3. CTA词典

优先使用：

- 阅读这篇文章
- 找到我的起点
- 开始完成这张卡
- 生成我的候选卡
- 进入现实验证
- 继续上次进度
- 返回上一页
- 返回文章中心
- 返回案例中心

禁止把“进入下一步”“点击查看”“了解更多”作为默认高优先级按钮。

## 4. 模式词典

- Paper：`阅读模式｜理解机制与证据`
- Field：`观察模式｜看时代与结构`
- Cockpit：`工作模式｜完成判断与行动`

模式变化只改变任务空间与材料感，不改变品牌、导航位置、按钮语法、返回路径和信任语言。

## 5. 导航规则

- A/B/C只高亮当前查询参数对应入口；
- 无参数 `/start/` 不伪装成A/B/C任一入口；
- A/B/C分别按3/4/2题计算进度；
- 历史状态与当前意图冲突时必须询问用户选择；
- 并列结果公开展示，并解释首个推荐规则。

## 6. 工具规则

- 默认值不计进度；
- 自动保存输入；
- 自动保存最终生成资产；
- 删除保存草稿不等于清空当前页面；
- 重置当前内容时同时清空相应本地资产；
- 综合诊断必须显示前置条件。

## 7. 阅读规则

- 移动端与桌面端都显示证据等级和来源边界；
- 文章显示当前位置；
- 同源进入时提供返回上一页；
- 案例可从 `/articles/?type=case` 直接进入；
- 文末必须有具体行动与返回路径。

## 8. 真实性规则

自动化验收只能证明结构存在和构建通过。

以下必须由5—8位真人测试验证：

- 30秒理解；
- 90秒入口；
- 导航完成；
- 工具完成；
- 回访连续性；
- 真实Outcome。

没有真人证据时统一保持 `NOT_RUN`。
