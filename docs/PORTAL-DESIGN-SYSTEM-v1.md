# 原力战略门户设计系统 v1.1

- 状态：`accepted / implementation-baseline`
- 上游设计正本：`moonstachain/yuanli-taste`
- 适用仓库：`moonstachain/yuanli-strategy-web`
- 核心裁决：不复制一套皮肤，而是移植“system 锁行为、theme 管外观、component 锁契约、page 管编排”的治理方法。

## 1. 为什么升级

门户的内容架构已经能够区分主题、栏目、战役、旗舰、正典与工具。设计系统要完成三个变化：

```text
好看的文章网站
→ 有独立品牌材料感的思想门户
→ 能阅读、能进入现场、能完成工作的战略界面
```

## 2. 纸—场—舱三态

### 纸｜Paper

适用：正典、书房、普通文章、案例长文。

目标：长时间阅读、证据辨识、概念理解。

特征：暖纸、墨色、窄正文、克制动效、清晰脚注与目录。

### 场｜Field

适用：首页、300年康波、原力群星志、商业物种志、原力反例志。

目标：让用户先看见时代、结构、位置和选择，再进入具体内容。

特征：暖墨绿、古鎏金、材料层次、大画幅叙事、时间线与结构装置。

### 舱｜Cockpit

适用：原力工具、诊断室、原力OS实验室与未来个人工作区。

目标：完成战略任务，形成输入、输出、状态、证据和下一步。

特征：高信息密度、明确状态、分步进度、本地保存、抽屉与工作面板。

## 3. 分层契约

```text
src/styles/tokens/system.css
锁定间距、字号、圆角、动效、层级和布局行为

src/styles/themes/*.css
只定义颜色、字体、光影、纹理和场景背景

src/styles/global.css
定义全站基础组件和无障碍行为

Astro components
锁定卡片、状态、证据、坐标和行动面板契约

pages
只组合内容，不自行发明新的视觉语言
```

## 4. 首页 v2：高密度场态

首页不再作为一篇长文章的封面，也不承担完整数据库展示，而是成为一张可进入的战略总图。

固定顺序：

```text
母承诺与生命链
→ 今日原力裁决与真实建设状态
→ 三部诊断入口
→ A1—C4 正典矩阵
→ 七栏目状态总账
→ 四旗舰观察场
→ 文章证据总账与筛选
→ 工具行动与六大主题
```

首页采用以下纪律：

1. **高密度不等于拥挤**：首屏同时提供定位、判断和行动，但每个区块只有一个主任务；
2. **状态不伪装**：文章、工具、栏目和旗舰均从真实数据生成，不用虚构数字制造繁荣；
3. **矩阵用于扫描**：A1—C4 和栏目总账优先支持比较与定位，不做十二张相同大卡片；
4. **旗舰必须有装置**：《300年康波》使用时间线，其他旗舰保持独立问题入口；
5. **筛选必须可降级**：没有 JavaScript 时文章仍完整可读，JavaScript 只增强筛选；
6. **首页是场，不是舱**：可以搜索、筛选和选择，但不承载复杂表单和个人数据工作流。

## 5. 迁入与不迁入

### 已迁入

- 非线性间距与字号阶梯；
- 统一圆角和1px上浮；
- 三档动效与 `prefers-reduced-motion`；
- 纸、绿皮书场、深色工作舱三态；
- 统一卡片、状态、Chip、焦点与面板；
- LocalStorage仅用于用户本机草稿和界面状态；
- 移动端菜单抽屉；
- 文章阅读进度和自动目录；
- 首页A1—C4矩阵、栏目总账、旗舰时间线和文章筛选。

### 不迁入

- 不把所有页面改成墨绿色；
- 不在普通文章使用毛玻璃、拖拽和重动效；
- 不引入React、StyleX或重型组件框架；
- 不将用户输入上传到服务器；
- 不因页面上线宣称用户体验或商业Outcome已验证；
- 不把策划基线显示成已发布内容。

## 6. 组件与数据契约

首批统一组件：

- `StatusChip`：栏目和证据状态；
- `EvidenceBadge`：hypothesis / derived / verified / canon；
- `ModuleCoordinate`：A1—C4坐标；
- `ActionPanel`：读后行动与验收；
- `.yl-card`：阅读卡、栏目卡、面板卡三种尺寸；
- `.progress-rail`：文章和工具进度。

首页数据必须优先来自：

- `src/data/modules.ts`；
- `src/data/themes.ts`；
- `src/data/columns.ts`；
- `src/content/articles/*`。

不得在页面中另建一套与正典漂移的模块、主题和栏目名称。

## 7. 交互原则

1. 互动必须服务任务，不为了炫技；
2. 阅读页稳定，工作页才允许状态、保存和重排；
3. 所有可操作元素必须有键盘焦点；
4. 重要状态不能只依赖颜色；
5. 动效只提示层级和因果，用户可通过系统设置降低；
6. 浏览器本地保存必须明确告知，并提供清除入口；
7. Output、Used、Validated、Compounding必须继续分层；
8. 筛选结果必须显示数量和无结果状态，并提供一键清除。

## 8. 工程验收

- Astro build与Pages部署通过；
- 首页、栏目、文章、工具四类核心界面进入统一Token系统；
- 首页和旗舰栏目使用场态，工具页使用舱态，文章页使用纸态；
- 移动端导航不再通过隐藏大量入口解决；
- 文章目录和阅读进度可运行；
- 工具草稿可在同一浏览器恢复和清除；
- 首页文章可按主题、模块、证据与关键词筛选；
- 键盘焦点可见，支持reduced-motion；
- 静态产物存在核心路由。

## 9. 真实性边界

本文件完成与工程部署通过，只能证明设计系统和界面Output存在。

以下仍需真实用户证据：

- 用户是否更快找到入口；
- 用户是否理解纸、场、舱的差异；
- 高密度首页是否提升还是降低理解效率；
- 阅读深度是否增加；
- 筛选功能是否被真实使用；
- 工具完成率是否提高；
- 设计是否形成Changed Rule和下一轮复用。
