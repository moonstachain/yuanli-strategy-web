# 原力战略Web栏目矩阵 v1.1

- 状态：`accepted / execution-baseline`
- 日期：2026-08-06
- 核心裁决：后台继续保留七个常设栏目与四个旗舰系列；前台只突出四个当前内容引擎，不再把所有治理对象并列给陌生用户。

## 1. 五层治理结构继续有效

```text
六大用户主题
→ 七个常设栏目
→ 阶段性媒体战役
→ 四个旗舰系列
→ A1—C4与证据/Outcome治理
```

- 用户主题回答“我从哪里进入”；
- 常设栏目回答“什么任务长期生产”；
- 媒体战役回答“本阶段集中解释什么冲突”；
- 旗舰系列回答“沉淀什么跨周期思想资产”；
- A1—C4回答“如何约束、检索、验证与回写”。

五种文章类型 `insight / canon / case / tool / library` 是生产任务，不是栏目。

## 2. 七个常设栏目

| 栏目 | 母问题 | 节奏目标 | 当前状态 |
|---|---|---|---|
| 原力前哨 | 时代正在改变怎样的选择环境 | 每周1个认知行动包 | live / 首战役已启动 |
| 原力正典 | 原力战略是什么，又不是什么 | 每月2—4篇 | live |
| 原力诊断室 | 我究竟卡在A1—C4哪里 | 双周1期 | planning-baseline |
| 原力案例库 | 方法在哪里成立或失效 | 每月1—2个 | execution-ready |
| 原力工具 | 读完后我能完成什么 | 随战役扩充 | live / 3张工具 |
| 原力OS实验室 | 系统如何建成、漂移与回写 | 双周或月度 | planning-baseline |
| 原力书房 | 文明经典如何解释原力战略 | 每周或双周 | execution-ready |

### 最低合同

每个常设栏目必须明确：

1. 稳定母问题；
2. 目标用户和症状；
3. A1—C4接口；
4. 固定内容协议；
5. 真实更新节奏；
6. 行动或下一步；
7. 证据与回写入口。

`live`只表示已有正式内容或工具可访问，不表示稳定节奏、Outcome或Compounding已经成立。

## 4. 当前四个前台重点引擎

```text
原力前哨
原力商业物种志
原力诊断室
原力OS实验室
```

理由：它们共同形成完整用户链：

```text
看见变化
→ 理解商业生命体
→ 定位自己的问题
→ 观察系统如何从结果变强
```

工具与正典作为稳定支撑入口。

## 5. 前台主导航

```text

商业物种
诊断室
OS实验室

```

- 案例由商业物种和诊断室承载；

- 书房作为栏目和文章来源类型保留。

## 7. 新增栏目治理门

在当前90天路线完成前不新增长期栏目。新增提案必须同时回答：

1. 它补哪个不可替代的内容对象；
2. 现有栏目为什么无法承载；
3. 服务哪个真实用户症状；
4. 连接哪个A1—C4模块；
5. 能否连续生产12个高质量选题；
6. 会挤掉哪个现有WIP；
7. 如何产生行动、证据与回写。
