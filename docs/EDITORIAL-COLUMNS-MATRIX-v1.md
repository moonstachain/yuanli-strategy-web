# 原力战略Web · 栏目矩阵 v2.1

- 状态：`governance baseline`
- 核心裁决：栏目是内容生产与治理结构，不再作为陌生用户首页的主导航结构

## 1. 前台与后台分工

### 首页前台只回答三类问题

```text
世界正在发生什么？
我当前最值得验证哪一环？
我现在可以完成什么？
```

### 栏目后台负责持续生产

```text
原力前哨
原力正典
原力诊断室
原力案例/商业物种
原力工具
原力OS实验室
原力书房
```

完整栏目状态通过栏目页、探索菜单和治理文档访问，不在首页平铺。

## 2. 当前四个运行引擎

| 引擎 | 用户问题 | 最小产品 | 当前WIP |
|---|---|---|---|
| 原力前哨 | 什么正在贬值，什么正在升值 | Signal＋Evidence＋Judgment＋Action | 首个战役“AI正在蒸馏你” |
| 原力商业物种志 | 公司如何成为不同于同行的新物种 | 一个关键选择＋事实包＋原力裁决 | 丰田/宜家/Costco候选，三选一 |
| 原力诊断室 | 我真实卡在哪一环 | 症状＋导航假设＋行动＋7/30天回访 | 先运行3分钟导航v0.1 |
| 原力OS实验室 | 一次结果如何改变下一次行动 | Task＋Gate＋Receipt＋Changed Rule＋Task2 | 首次用户旅程构建复盘 |

## 4. 内容角色

每个媒体战役最多包含：

- Hook：获得注意；
- Evidence：约束事实边界；
- Mechanism：形成原力解释；
- Action：推动现实动作；
- Reflection：记录Outcome与Changed Rule。

内容角色不是永久栏目。

## 5. 首页呈现规则

首页不再展示：

- 七栏目状态表；
- 四旗舰并列说明；
- 完整文章总账；
- 主题/模块/证据多维筛选；
- `live / execution-ready / planning-baseline`工程状态。

首页允许展示：

- 一个当前战役；
- 一个本月主展；
- 三个现实症状入口；
- 三个工具收益卡；
- 三条阅读轨道；
- 一句证据承诺。

## 6. 旗舰治理

采用“一个主展＋其他候选”的WIP结构。

当前优先级：

1. 原力商业物种志：未来90天主展；
2. 300年康波：年度研究资产；
3. 原力群星志：人物叙事候选；
4. 原力反例志：待真实失败证据后运行。

不删除任何旗舰，但同一时间只允许一个深度事实包争夺主WIP。

## 7. 栏目稳定运行门

栏目页面存在只证明Done。

稳定运行至少需要：

- 明确Owner；
- 固定节奏至少连续3个周期；
- 输入来源与发布门；
- 用户行动出口；
- Outcome问题；
- 复盘与Changed Rule入口。

当前未满足的栏目继续保持planning或execution-ready，不得因首页出现而宣称stable。

## 8. 禁止事项

- 不用栏目数量证明媒体成熟；
- 不把旗舰当高频资讯流；
- 不把战役角色变成新栏目；
- 不在Web复制Content Engine经营总账；
- 不以页面上线替代真实栏目节奏；
- 不把3分钟导航结果包装为经验证诊断。
