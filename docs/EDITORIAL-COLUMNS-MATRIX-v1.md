# 原力战略门户栏目矩阵 v1.0

- 状态：`accepted / execution-baseline`
- 项目：`moonstachain/yuanli-strategy-web`
- 目标：区分用户主题、常设栏目、媒体战役、旗舰系列、正典模块与工具，形成统一栏目总账。
- 最高纪律：栏目存在不等于内容成熟；页面存在不等于Outcome。

---

## 1. 总裁决

门户不是把所有内容标签并列在导航中，而是建立五层结构：

```text
六大用户主题
→ 七个常设栏目
→ 阶段性媒体战役
→ 四个旗舰系列
→ A1—C4后台正典与证据治理
```

其中：

- 用户主题回答“我从哪里进入”；
- 常设栏目回答“什么内容长期持续生产”；
- 媒体战役回答“本阶段集中解释什么结构冲突”；
- 旗舰系列回答“沉淀什么跨周期思想资产”；
- A1—C4回答“如何治理、检索、关联与回写”。

五种文章类型 `insight / canon / case / tool / library` 是生产任务，不再被误写为五个并列栏目。

## 2. 七个常设栏目

| 栏目 | 母问题 | 主要职责 | 建议节奏 | 当前状态 |
|---|---|---|---|---|
| 原力观察 | 时代正在改变怎样的选择环境 | 热点、结构变化、原力裁决 | 每周1—2篇 | execution-ready |
| 原力正典 | 原力战略是什么，又不是什么 | 三部十二模块、边界与误解 | 每月2—4篇 | live |
| 原力诊断室 | 我究竟卡在A1—C4哪里 | 真人症状、贵任务、最小动作 | 双周1期 | planning-baseline |
| 原力案例库 | 方法在哪里成立或失效 | Baseline、Action、Outcome、反例 | 每月1—2个 | execution-ready |
| 原力工具 | 读完后我能完成什么 | 诊断、卡片、实验与回写 | 随内容扩充 | live |
| 原力OS实验室 | 系统如何建成、如何漂移 | 文脉、大脑、地图、链路、Agent实录 | 双周或月度 | planning-baseline |
| 原力书房 | 文明经典如何解释原力战略 | 学科、模型、人物、著作 | 每周或双周 | execution-ready |

### 常设栏目最低合同

每个常设栏目必须明确：

1. 稳定母问题；
2. 目标用户和症状；
3. A1—C4接口；
4. 固定内容协议；
5. 真实更新节奏；
6. 行动或下一步；
7. 证据与回写入口。

没有稳定母问题、更新节奏和行动出口的内容，只能作为标签、专题或候选，不升级为栏目。

## 3. 四个旗舰系列

| 旗舰系列 | 研究对象 | 核心问题 | 当前状态 |
|---|---|---|---|
| 原力时代志｜《300年康波》 | 时代与选择环境 | 世界为什么在那个时刻换轨 | planning-baseline |
| 原力群星志｜《世界差一点走向另一条路》 | 人物与命运临界点 | 谁在答案未知时作出不同选择 | planning-baseline |
| 原力商业物种志｜《一家公司如何成为新物种》 | 企业与商业系统 | 原力如何变成品类、链路、控制权与OS | planning-baseline |
| 原力反例志｜《那些看起来正确却没有成立的战略》 | 失败、边界和反证 | 方法在什么条件下失效 | planning-baseline |

四个旗舰共同构成：

```text
时代提供选择环境
→ 人物作出关键选择
→ 企业把选择变成商业物种
→ 反例检验方法的适用边界
→ 工具把历史与案例转回今天的行动
```

旗舰系列不追求高频。任何篇目进入WIP前必须完成事实包、争议和反例、类比边界、行动出口与专业审阅。

- 栏目承诺；
- 母问题；

## 6. 状态语言

```text
live
已有正式内容或工具可访问

execution-ready
协议与候选已建立，可进入生产，但不能宣称已稳定运行

planning-baseline
栏目蓝图存在，事实研究、写作、真人行动或Outcome尚未发生
```

禁止用“已上线栏目”统称所有外显页面。

---

## 7. 新增栏目治理门

在本轮90天路线完成前，原则上不再新增长期栏目。新增提案必须同时回答：

1. 它补的是哪个不可替代的内容对象；
2. 现有栏目为什么无法承载；
3. 它服务哪个真实用户症状；
4. 它连接哪个A1—C4模块；
5. 至少能连续生产12个高质量选题吗；
6. 会挤掉哪个现有WIP；
7. 如何产生行动、证据与回写。
